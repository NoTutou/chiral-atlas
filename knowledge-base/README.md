## 证据口径

优先使用 CVE 官方 CNA JSON、PX4 仓库安全公告、原始 Issue 与维护者回复、修复 PR、GitHub Security Lab 及 MAVLink 官方文档。中文分析是这些材料的人工归纳；标注“整理建议”的内容是处置建议，不冒充厂商发布结论。每个章节列出该档案的参考证据，具体原话和代码应继续核读来源。

主评级依次优先 CVSS 3.1、3.0、4.0、2.0；同版本优先 CNA，其余来源和向量全部保留。没有权威评分的报告显示“未评级”，不沿用原表主观的 High/Medium。GHSA 只有等级没有分数时保留该等级，并标注无分数。

存在重要差异的例子：CVE-2026-32709 的正文写 Critical 9.8，但公告结构化数据和 CNA 为 Medium 5.4；CVE-2024-30799 的 RCE 声明缺少引用 Issue 的支持；CVE-2024-38952 原报告明确未复现；CVE-2024-40427 的 ASan 证据是越界读取。页面同时呈现这些限制。CVE-2025-5640 等条目的 CVSS 版本差异和链路前提也保留。

修复 PR 已合并不等于已发布版本。PR #22531 未合并，不能当作完成修复；#18371、#22834 已合并，但未从现有材料确认首次修复发布版本。未确认的信息明确留空或注明待确认。

GHSA-5hvv-q2r5-rppw ↔ CVE-2023-46256、GH-ISSUE-23251 ↔ CVE-2024-38951、EDB-52339 ↔ CVE-2025-5640 各共用一个问题组。其他相似组件问题仅标记“相关机制”，不自行合并 CVE。

## 快照与限制

JSON 快照可能已格式化或从公告索引提取；SHA-256 校验本地保存文件，不声明与服务器原始字节一致。Exploit-DB 页面直接抓取返回 403，文件保存的是网页核读的人工摘要。PR #18371、#22531、#22834 在 GitHub API 限流后使用网页核读记录；文件及 manifest 中明确注明，不伪装成完整 API 响应。原始 PoC 没有执行。

外部页面可能后续修订。`retrievedAt` 是采集/核读时间；来源首发/更新来自原材料；二者与本机复现状态不同。原表的日期或等级有误时仅在输入副本和导出“原始行”中保留，不用于页面主统计。

## 更新流程

在项目根目录执行：

```sh
python3 tools/collect_vulnerabilities.py --refresh
# 阅读来源变化，更新 knowledge-base/curation.json 和必要的关联规则
python3 tools/build_knowledge_base.py
python3 tools/check_knowledge_base.py
npm run build
```

采集遇到限流、403 或其他错误会报告失败；不能把失败后保留的缓存称为新核验。改写人工核读记录时同步更新 manifest 的核验时间与校验值。生成脚本不自动把新公告全部加入页面，需要先人工整理。

网站运行不依赖 Python、联网查询或数据库。数据随 Vite 构建嵌入单文件，收藏保存在本浏览器；旧示例收藏 ID 会自动清理。导出与送入推演携带完整来源、评分和不确定项。版块 3 的现有规则引擎与样例不在本次更换范围内。
